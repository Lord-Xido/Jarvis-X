# Auto-Executing Bytecode & 3D Geometry Pipeline\n\nThis browser demo visualizes a compact bytecode instruction stream driving a recursive Three.js geometry field.\n\n## Run\n\nOpen `index.html` in a modern browser with network access to the Tailwind and Three.js CDNs.\n\nControls:\n\n- **Pause/Resume Stream** — toggles the simulated instruction clock.\n- **Step Once** — advances one opcode.\n- **Reset PC** — returns the program counter to the first instruction.\n- **Recursion Depth** — rebuilds nested voxel geometry from `2^N`.\n- **Execution Frequency** — scales the browser animation and instruction cadence.\n\n## Operational boundary\n\nThe disassembly, registers, addresses, and GHz values are an interactive visualization of a bytecode/geometry pipeline. They are not measurements of the host CPU, GPU, or an executing native Jarvis-X backend.\n\nThe browser-side state machine maps the conceptual instruction sequence\n\n```text\nLDX.V3 -> SHL.IMM -> MAT4.MUL -> RAST.DIR -> SYNC.FB -> JMP.RET\n```\n\nonto an animated 3D geometry root. This keeps the demo auditable and consistent with Jarvis-X's evidence-gated distinction between a visualization and a deployed runtime.\n

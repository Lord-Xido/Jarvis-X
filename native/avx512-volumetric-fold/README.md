# AVX-512 volumetric fold kernel

This module is the native, bounded reference implementation of the supplied
`vOmegaXi+` 512-bit recursive fold primitive.

## Exact state size

An `8192 x 8192 x 8192` **bit** lattice contains:

- `8192^3 = 2^39 = 549,755,813,888` bits;
- `2^36 = 68,719,476,736` bytes = **64 GiB**;
- `2^33 = 8,589,934,592` `uint64_t` words = **0x200000000 words**.

The earlier `0x40000000` word constant describes only 8 GiB. This module does
not hard-code either size: `total_words` is supplied by the caller so smoke
tests can use small buffers and a production runtime can bind the logical space
to sparse, mapped, or out-of-core storage.

If all three logical buffers (`src`, `dst`, `entropy`) are fully resident at the
full 8192^3 extent, the raw payload is 192 GiB before allocator/page-table
overhead. The kernel itself has no hidden persistent state; the explicit buffers
are the state.

## Transform

For every 512-bit source block, the kernel loads the block at the corresponding
reverse **block** position and applies:

```text
next    = (src & mirror) ^ (~src)
        = (~src) | mirror
entropy = next ^ src
```

The AVX-512 implementation uses `VPTERNLOGQ imm8=0xCF`, which is the truth table
for `(~A) | B` when `A` is the source block and `B` is the mirrored block.

The supplied zero-block bypass was intentionally removed from the exact path.
For `src=0` and `mirror=0`, the stated Boolean transform yields all ones, not
zero. Skipping that block therefore changes the mathematics rather than merely
optimizing it.

## Geometry boundary

The mirror is a **512-bit blockwise reverse traversal**. Lanes are kept in the
same order within each mirrored block. This is faithful to the supplied
`mirror_index = total_words - index - 8` rule, but it is not a per-bit central
inversion of a 3D voxel lattice. A true `(x,y,z) -> (N-1-x,N-1-y,N-1-z)` bit
reflection would additionally require reversing word order inside the 512-bit
block and reversing the bit order inside each 64-bit word, or an explicit
coordinate mapping.

## ABI and ISA

`volumetric_fold_avx512.S` is preprocessed GNU/Clang assembly and supports both:

- System V AMD64: `rdi,rsi,rdx,rcx` arguments;
- Windows x64: `rcx,rdx,r8,r9` arguments.

The vector kernel requires AVX-512F and AVX-512DQ. `volumetric_fold.c` provides a
runtime dispatcher and a scalar reference fallback, so systems without AVX-512
retain identical blockwise semantics.

Buffers must be non-overlapping. `total_words` must be a multiple of eight.
Loads and stores are unaligned (`VMOVDQU64`), so 64-byte alignment is a
performance property, not a correctness requirement.

## Build and test

```bash
cd native/avx512-volumetric-fold
make test
```

To prove that the same assembly preprocesses to a Windows x64 COFF object:

```bash
make windows-object
```

The raw instruction bytes are deliberately **not** hand-maintained in source.
They are generated by the assembler from the canonical assembly so control-flow
and displacement bytes cannot silently become stale when the kernel changes.
